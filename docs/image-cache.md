# 画像を差し替えても反映されないとき

策定: 2026-09-22（pek2026対応時、`title.png`を同名で差し替えても変わらなかった）

## 決めたこと

`next.config.mjs`の`images.minimumCacheTTL`を60秒にした（Next 16の既定は14400秒 = 4時間）。
画像最適化（`/_next/image`）経由の画像は最長60秒で反映される。

2026-11-17 追記: インターミッション画面の背景・ヘッダーロゴ・ローディングアイコンは、表示を速くするため
`unoptimized`（元ファイルを直接配信）に変えた。これらは下の表の3層目（Service Workerプリキャッシュ）の
対象になり、1・2層目は関係しなくなった。画像最適化を通るのはメニュー画面のロゴ（`/intermission.png`）だけ。

| | 最適化経由（変更前） | 直接配信（現在） |
| --- | --- | --- |
| 取得 | 毎回サーバー処理を通る。ブラウザの保存は60秒 | 静的ファイル。2回目以降はService Workerのキャッシュから（通信なし） |
| 同名で差し替えたとき | 最長60秒で反映 | 新しいService Workerが有効になるまで古いまま（アバター・Page3画像と同じ） |

## 背景

画像が古いまま出るのはキャッシュが3層あるため。

| 層 | 何が起きるか | 効く環境 |
| --- | --- | --- |
| Next画像最適化キャッシュ | `next/image`の画像は`.next/dev/cache/images/`（本番は`.next/cache/images/`）にサーバー側で保存される。キーはURL・幅・品質だけで元ファイルの更新時刻を含まないので、期限内は同名で差し替えても古いまま | dev / 本番 |
| ブラウザHTTPキャッシュ | 本番は`Cache-Control: max-age=<minimumCacheTTL>`。devは`max-age=0`だがNext側のETagが古ければ304で古い画像が残る | 本番 / OBS |
| Service Workerプリキャッシュ | ビルド時に`public/`配下のうち、`src/staticConfig`が参照しているイベントのフォルダと共有フォルダ（2MiB以下のファイル）がプリキャッシュされる（`<img>`直参照のアバターやPage3画像に影響。`next/image`のURLは対象外）。新しいSWは全タブを閉じるまで待機するので、OBSを開いたままだとデプロイ後も差し替わらない | 本番のみ |

`minimumCacheTTL`は1層目と2層目の期限を同時に決める。画像は数枚しかないので60秒でも負荷は問題にならない。

## 今すぐ直したいとき

- dev: `rm -rf .next/dev/cache/images`（サーバー再起動不要）
- 確実に効かせたい: ファイル名を変える（キーがURLなので全層に効く）
- 本番のOBS: ブラウザソースを一度閉じて開き直す（待機中のSWを有効化する）
- 本番でキャッシュごと消したい: `/tools/cache`の「すべて消して再読み込み」（そのブラウザだけが対象）
